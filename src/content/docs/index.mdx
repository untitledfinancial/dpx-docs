## TL;DR

DPX is the payment and settlement layer for the agentic internet. Any autonomous agent can call `/manifest` to discover DPX, `/flow-estimate` to preview a full settlement response before committing, `/quote` to get a binding fee, and `POST /settle` to authorize on-chain execution — no onboarding, no API key, no human step. The x402 intelligence fee payment authorizes the oracle signal and quoteId. Settlement execution is sender-funded: DPX returns execution parameters and the caller calls `router.settle()` on-chain, paying their own gas. A 9-layer Stability Oracle gates every settlement on real-world conditions — climate, macro, FX, geopolitical — and holds automatically when conditions are UNSTABLE. ESG scores are a congestion fee, not a gate: every counterparty can settle, higher-impact activity simply costs more, and 100% of ESG fees are redistributed to verified on-chain impact programs. MCP-native, x402-native, ISO 20022-compatible. Contracts live on Base mainnet.

For fully autonomous operation, the settlement agent supports four AI origination modes: `execute: true` initiates Mercury payments immediately after AI approval; `aiRoute: true` selects the optimal corridor from a list of accepted currencies; sweep rules fire Mercury payments when oracle conditions clear on a schedule; and hedge rules execute automatically when the Butterfly cascade signal fires. See [AI Origination](/agent-quickstart#ai-origination-modes).

## What DPX does

DPX is the financial action layer for AI agents — settlement infrastructure where any autonomous agent can discover, price, comply, and execute a cross-border payment end-to-end without human intervention. An agent calls `/manifest` to discover capabilities, `/quote` for a binding fee, `/flow-check` for compliance preflight, and `POST /settle` to execute. No API key. No account. No onboarding.

Smart contracts are designed to be agent-executable. APIs are machine-readable by default. Every layer used by human treasury teams is equally accessible to software agents making real-time financial decisions. DPX speaks MCP natively (81 tools), implements x402 for machine-native micropayments, publishes an A2A agent card so orchestrators can discover it at runtime, and is ISO 20022-compatible for any existing treasury system that needs to connect.

The Stability Oracle gates every settlement on real-world conditions — continuously recalibrating across climate, macro, FX, and geopolitical signal layers. If conditions are UNSTABLE, a hold is automatic; when they clear, execution resumes. Every API response includes structured reasoning, a confidence score, and a forward-looking outlook. Treasury teams and AI agents receive the same signal — there is no separate "human" and "machine" interface.

ESG logic is encoded directly into transaction mechanics, not bolted on. Every transfer carries a live ESG score that determines the fee applied to it. Higher-impact activity costs less; higher-harm activity costs more. These fees are not absorbed into a generic treasury — they are programmatically redistributed in real time to sector-specific impact channels. Fossil fuel-linked flows may fund ocean restoration; fashion-related flows may fund garment worker protections. Every redistribution is traceable on-chain.

DPX runs a live prediction ledger. Every forecast — regime transition probabilities at 30, 60, and 90-day horizons — is stored at the time it is made and scored against the realised outcome when the horizon arrives. Accuracy scores accumulate over time, feeding back into signal weights via weekly recalibration. There is no fixed version of DPX. There is only the version running now, which is always more informed than the one before it.

## Agent discovery

Agents and LLMs find DPX at these standard locations:

```
GET /llms.txt                          LLM navigation index (llmstxt.org standard)
GET /llms-full.txt                     Complete docs compiled for LLM context
GET /openapi.json                      OpenAPI 3.0 schema for all endpoints
GET /.well-known/agent.json            A2A Agent Card (Google A2A / ADK spec)
GET /.well-known/ai-plugin.json        Agent framework plugin manifest
GET /manifest                          Live DPX protocol manifest with fee config
GET /feedback-signal                   30-day corridor history — hold rate, confidence, volume
```

**A2A Agent Card** — `/.well-known/agent.json` on `agent.untitledfinancial.com` is a protocol-compliant [Google A2A](https://google.github.io/A2A/) discovery document. Orchestrating agents (Vertex AI ADK, CrewAI, LangGraph) poll this at runtime to discover DPX capabilities, JSON input schemas, and x402 payment requirements without prior knowledge of the protocol.

**Reports:** [reports.untitledfinancial.com](https://reports.untitledfinancial.com) — AI-synthesized institutional reports (climate, macro, ESG, compliance, treasury) gated via x402. Pay per report in USDC on Base mainnet. Agent card at `/.well-known/agent.json`.

**Status:** [status.untitledfinancial.com](https://status.untitledfinancial.com) — live health checks across all 10 services with D1-backed analytics.

**MCP registries:** [Anthropic official](https://github.com/modelcontextprotocol/servers) · [Smithery](https://smithery.ai/server/@untitledfinancial/dpx-mcp) · [mcp.so](https://mcp.so) · [npm](https://www.npmjs.com/package/@untitledfinancial/dpx-mcp)
